# Agent harness plan (revision 4)

Persistent plan and decision record for turning Vernier from "hotkey → screenshot → answer" into a real-time, context-aware desktop partner. It is written to survive context compaction: status, decisions and review findings live here, not in a chat log.

Roles: **Agent A** (architect/implementer) and **Agent B** (critical reviewer, a persistent reviewer agent consulted at each checkpoint). B's findings and A's responses are logged in §6.

## 3. Architecture decisions (ADR log)

- **ADR-1 One tool registry, one executor, two transports.** `Vernier.Core.Tools` defines `ToolDefinition`, `ITool`, `ToolExecutor` (resolve → validate → policy → approval → execute → wrap). Native function calling (Anthropic, OpenAI-compatible, Gemini) and the loopback MCP server both call the same executor. *Why:* openclaw enforces the same pre-execution boundary for MCP and native paths; anything else lets one path bypass policy.
- **ADR-2 Loopback HTTP MCP server inside the app, per-turn grants.** `HttpListener` on 127.0.0.1, random port, random 32-byte bearer token minted per turn with an allowlist of tool names, revoked when the turn ends; enforcement is server-side. *Why:* verified that Claude Code 2.1.296 connects to it and calls tools mid-answer; the overlay, capture and approval UI live in the app process, so no stdio bridge process is needed. *Rejected:* `Vernier.exe --mcp-stdio` relay (extra process and pipe for no gain while the app is running).
- **ADR-3 The model names targets; Vernier resolves them.** Drawing and action tools take a `target` that is an element id or text id from the current observation, a text query, or (fallback) a pixel box in the frame. Resolution: UIA → OCR boxes → box. Results report which method placed the mark and its confidence. *Why:* clicky and open-computer-use both show naming-then-grounding is more accurate than pixel guessing; hacky shows what goes wrong when the local index is empty.
- **ADR-4 Keep WPF for the overlay; fix the renderer, not the stack.** *Confirmed by experiment (M1):* a DWM-composited window (no `AllowsTransparency`, `DwmExtendFrameIntoClientArea(-1)`, built both as a WPF `Window` and as a raw `HwndSource` with the layered style at creation) was transparent but gave no latency gain on an empty glass (6.4–6.6 ms vs 6.1 ms median), and click-through was lost both ways because WPF does not keep `WS_EX_LAYERED` without per-pixel transparency. Kept the layered glass. Measurement shows a single mark reaches the screen in ~5 ms on an empty glass; the cost is the immediate-mode redraw of everything. Retained `DrawingVisual`s remove that. A C++/DirectComposition renderer is not justified by the data and would add a language. Re-measure after M1; revisit only if p95 with a full glass stays above one frame budget (33 ms).
- **ADR-5 Observation is event-driven and local; model calls stay user-initiated by default.** Foreground/title changes (WinEvent hook), media session (Windows GSMTC), browser address (UIA), selection — collected locally into a timeline with timestamps and sources. Nothing is sent until the learner asks, except the opt-in proactive checks (ADR-8).
- **ADR-6 Video context only from legitimate sources.** Playing media: title, app and position from Windows' media session API. YouTube URL: title/author via the public oEmbed endpoint (network, only when asked). Local file: frames at a timestamp via Windows media APIs; captions only from a subtitle file next to the video. No scraping of private caption endpoints; when only metadata is available the tutor is told so.
- **ADR-7 Routing is explicit.** Settings hold a route per task category (quick, tutor, vision, coding, review). The ask bar shows the model and lets the learner override per question. Auto-routing by category is opt-in. Every turn records route, latency and tokens.
- **ADR-8 Proactivity is a local decision layer with a budget.** Local triggers (repeated rewinds of the same video segment, an error dialog or compiler error in focus, long dwell on one page after a question) score relevance; a suggestion chip appears only above a threshold, inside an interruption budget, and not again after dismissal. Sending anything to a model proactively is a separate opt-in, off by default.
- **ADR-9 Knowledge writes are proposals applied in a transaction.** Search → dedupe (normalise, aliases, Jaro-Winkler with graphify's guards) → proposal with expected hashes → learner approves → journaled apply with backups and rollback; each new note also updates the subject index in the same transaction. The model has no apply tool.
- **ADR-10 Connectors are plugins behind one interface.** `IConnector` with scopes, status, connect/disconnect (revoke + delete secret), and tools; tokens only in Credential Manager. Google Docs uses OAuth PKCE with a learner-supplied OAuth client id and `drive.file` scope.

## 4b. Revision 5 plan (owner request of 2026-10-16)

### Reflection: what the owner asked for, across both sessions

The original directive was a real-time, context-aware desktop partner: the model decides *what* help is useful, the harness decides *how* it is done reliably. Context was named as the largest limitation. Revision 4 delivered the tool harness (drawing as tools, MCP, native tool calling, routing, a first context hub), but left context as an opt-in add-on that samples metadata, and left computer use, knowledge, proactivity and connectors unbuilt.

The new request sharpens four things:
1. **Context is the core, always on, built by code.** Not a per-question patch: a system that runs over time, keeps a structured memory of the learner's work, and hands any model the relevant part. A model may enrich it, but only as an optional alternative (free: local or OpenRouter free tier).
2. **C++ where the platform makes it faster, not as a rewrite.** Native code is justified only where it reaches a Windows facility C#/WPF cannot use well: GPU screen duplication with dirty rectangles, WIC scaling/encoding, and a compositor-driven light that never waits on the UI thread.
3. **The UI should have depth and taste:** real Windows materials and elevation, a real travelling wave on the capture light (the current one is a banded opacity mask), colour themes, and type that renders mathematics properly (x², stacked fractions, roots), with a face that has character instead of Bahnschrift.
4. **Finish the remaining milestones** (computer use, knowledge, proactivity, connectors, docs/publish).

### Decisions

- **ADR-11 Native module `Vernier.Native` (C++20, C ABI, one DLL), three parts only.** (a) DXGI Desktop Duplication: acquires frames on the GPU, reports dirty and move rectangles, keeps a 64×40 grayscale context thumbnail and copies only the regions asked for. This replaces BitBlt for continuous observation (change detection becomes free and exact) and for asks (no 70–90 ms GDI copy, no CAPTUREBLT cursor flicker). (b) WIC high-quality downscale + PNG encode of a BGRA buffer, replacing the WPF imaging path. (c) A DirectComposition/Direct2D edge light on its own render thread, so the wave animates at display rate even while WPF is busy. Every native call has a managed fallback (GDI capture, WPF encoder, WPF strips); a missing or failing DLL degrades, it never breaks the app. *Rejected:* a native overlay for marks (WPF retained visuals are already within one frame for normal use; the heavy-glass p95 is noted, not worth a second renderer); rewriting OCR/UIA (already native OS services).
- **ADR-12 Context engine replaces the context hub.** Sources are events, not polls where possible: WinEvent hooks for foreground and title changes, the media session, the browser address, native dirty-rect deltas, and local OCR of the region that changed once it has settled. An *episode* is a stretch of work on one app and document (normalised title, page address or media item). Each episode accumulates time, media positions and rewinds, entities found on screen (equations, headings, identifiers, file names), questions asked and marks drawn. Episodes persist in SQLite (schema v3) with retention; screen text itself stays in memory only. At ask time the engine ranks episodes and facts against the question (recency × term overlap) and renders a bounded, sourced, aged block. An optional context model (local Ollama vision model or an OpenRouter free model, chosen by the learner) can add a one-line summary when an episode closes; nothing depends on it.
- **ADR-13 Always-on with consent and visibility.** Metadata context (apps, titles, media, address) is on by default and disclosed at first run. Reading screen content continuously (local OCR of changed regions) runs once the learner has allowed screen capture, is local only, skips private windows and password managers, pauses in Share-Safe and Pause, and is shown by a steady indicator (tray icon dot and the bar footer). Sending anything to a model still needs a learner action, except opt-in proactive checks. CLAUDE.md is updated to say exactly this.
- **ADR-14 Free models are presets, not a dependency.** OpenRouter (OpenAI-compatible, free models need a free key) and local servers (Ollama/LM Studio, no key) are offered as providers for the context route and any task route. No model is called in the background unless the learner picks a context model.
- **ADR-15 Answers render as typeset text.** Answers become a rich document: paragraphs, emphasis, lists, inline and display math. Math uses TeX notation, typeset by WpfMath 2.1 (MIT; OFL fonts); the model is told to write `\( … \)` inline and `\[ … \]` for display (after review R3: `$` collides with money). `$…$` is still accepted when it clearly holds maths; a caret exponent in plain text (`x^2`, `10^{-3}`) becomes a real superscript; an unterminated delimiter stays text while streaming. Reading text and headings use Sitka (Text / Subheading / Heading optical sizes), which ships with Windows, so nothing is bundled; UI chrome keeps Segoe UI Variable. Every formula has a spoken accessible name ("a over b") and speech reads formulas as words.
- **ADR-16 Depth from the platform first.** Windows 11 Mica/Acrylic backdrops and rounded corners through DWM attributes; a three-level elevation scale (shadow + top highlight); motion that settles rather than bounces. Colour themes are presets that keep the role rule: the learner's ink stays marker yellow, the tutor's colour is the theme's cool accent.
